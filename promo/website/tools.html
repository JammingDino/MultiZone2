Movement III

C

Apparatus.

— what a zone can actually reach

A model that can only talk is a demo. Every tool below is enabled per zone, with its own approval policy, and every one of them runs from your machine, so a scout that only reads and an implementer that may edit are two different instruments, not two prompts.

Web

tutti

bar 1

Seven engines. No API key.

smart_search queries seven keyless engines in parallel and merges them with Reciprocal Rank Fusion, so a page several engines agree on ranks highest. If one is blocked or rate-limited the others still answer, and the result tells you which engines contributed and which failed, rather than quietly returning less.

smart_search "tauri v2 updater signature verification"

Engines in parallel

    Fused ranking RRF

      Illustrative results, written for this page

      smart_fetch

      Reads one or more pages or PDFs in full as clean markdown, boilerplate stripped, with an optional relevance query to trim a long page down to what matters.

      smart_crawl

      Follows links within one site and reads several pages in a single call, visiting the most relevant first.

      All three run through a browser-emulating HTTP client carrying a real Chrome TLS/HTTP-2 fingerprint. There is no headless browser, so a page that renders entirely via JavaScript, or sits behind an interactive bot challenge — is reported as such rather than returned blank. A tool that lies about an empty page is worse than one that cannot read it.

      Terminals

      sostenuto

      bar 26

      A command that finishes can't start a server.

      run_command runs something and waits for it to exit, which cannot express starting a thing — a dev server, a REPL, a log to follow, a program that asks a question part-way through. The terminal group keeps a process alive between calls instead.

      t1 dev server · inherited project directory alive 
      
          
      
            
            Six calls, one process, output collected between them.
          
      
        
      

        
      
          
      
            
      ToolWhat it does
      
            
              
      terminal_startStart a process (or a bare shell) and get back a short id — t1. Returns immediately; the process keeps running.
      
              
      terminal_writeType into it: a command, an answer to a prompt, a password. Returns only the output that followed.
      
              
      terminal_readRead what it has printed. Pass back the cursor from a previous call to get only what is new.
      
              
      terminal_listThe conversation's terminals: label, whether each is alive, how much output is waiting.
      
              
      terminal_stopStop one, or all, and return the final output.
      
                  
          
      
        
      

        
      
          
      
            
      Timing is the hard part
      
            
      Driving an interactive program is a timing problem, so every call that can wait takes delay_ms (wait before typing — start a server, send the sudo password five seconds later), wait_for (a regex, with timeout_ms, reporting whether it matched), or wait_ms (collect for a fixed span).
      
          
      
          
      
            
      Nothing is lost between calls
      
            
      Reader tasks drain stdout and stderr continuously, so output printed between tool calls is still there when you look. ANSI escapes are stripped and a \r-redrawn progress line collapses to where it landed. Terminals are visible to the whole session — a leader's dev server is one its own sub-agents can query.
      
          
      
        
      

        
      
          
          
      
            stdin/stdout are pipes, not a PTY. Servers, build tools and REPLs work;
            programs that insist on a real terminal do not. Pass sudo -S, expect
            ssh password prompts and full-screen TUIs to fail, and stop a process with
            terminal_stop rather than sending Ctrl-C. Children block-buffer on a pipe, so
            unbuffer where it matters — python -u, stdbuf -oL;
            PYTHONUNBUFFERED is set for you.
          
      
        
      
      
      
    
      
  
      

      



      
  
      
    
      
      
      
        
      Replay
      
        
      da capo
      
        
      bar 58
      
      
      
      
      
        
      “Where did that number come from?”
      
        
      
          The clock icon in the chat header opens Replay — the run as it actually
          happened, at whatever pace you read at. It is not the transcript scrolled back: it carries
          the parts the transcript never had, like an approval you declined, a tool that failed, a zone
          that switched mid-turn, or a plan you rewrote before approving.
        
      

        
      
          
      
            
            00:00.0 · 14:22:07
            
      
          
      
          
      
            
            
          
      
          
        
        
        

        
        Illustrative run, written for this page
        

        
        
          Each row shows elapsed time from the first event alongside the wall clock. Play steps
          at a fixed cadence for skimming, the chips filter by kind, and every tool call carries its
          arguments, its output and how long it took, which is the point. That question is answerable
          after the fact, not only while it scrolls past.
        
        
      
        
    
        
  
        

        



        
  
        
    
        
      
        
        
        Voice
        
        
        parlando
        
      
        
      
        
        
        Drop a two-hour recording into a text-only model.
        
        
        
          Dictation goes to a provider you configure, using the OpenAI-compatible
          /audio/transcriptions endpoint — point it at a local server running Whisper and
          your audio never leaves the machine. It behaves like typing: start a recording with text
          selected and what you say replaces the selection.
        
        
        
        
          But the part that changes what you can do is the audio upload. Drop an MP3,
          WAV, M4A, MP4, FLAC, OGG or WebM into any composer and it is transcribed through the same
          provider and sent as text. The model never sees audio, which means any zone works,
          including models with no audio input at all. A meeting recording you would never sit through
          dictating in real time is one drag away from being something you can ask questions about.
        
        

        
        
          
        
            
        SettingOptions
        
            
              
        When a transcript is readyUse it — the words go straight into the message box. Review first — the chip holds the transcript for you to read and correct, then Use as message.
        
              
        How it reaches the modelAs my message — the transcript is the text you send. As an attachment — the model gets the full transcript as context while the message box stays yours. That is the mode for anything long: attach the meeting, then type “what did I agree to?”
        
              
        Timestamps and languageAsks the endpoint for verbose_json: duration, detected language, and [0:00]-stamped lines, marking any passage the model itself flagged as unclear. Not every server implements it; one that doesn't still returns a plain transcript.
        
                    
          
        
        
        

        
        
          
          
        
            There are no speaker labels. OpenAI's transcription endpoint does not
            diarize, and a guess at who was talking, presented as data, is worse than not offering it.
          
        
        
        
      
        
    
        
  
        

        



        
  
        
    
        
      
        
        
        Connectors
        & API
        
        
        attacca
        
        
        bar 92
        
      
        
      
        
        
        The app can be driven, including by the model.
        

        
        
          
        
            
            
        MCP connectors, self-starting
        
            
        A catalog entry carries everything except the part only you have. Installing one writes the server and stops — nothing is launched until you press Connect. From the next launch, every enabled server connects in the background, so its tool list is current before the first message.
        
          
        
          
        
            
            
        Diagnose, in failure order
        
            
        Is the server enabled, is there a command, is that program on the PATH the app inherited, are the required values filled in, and only then the handshake. It reports the first false one. A stdio server's own stderr is captured, so “the command ran, the server exited, GOOGLE_CREDENTIALS_PATH is not set” replaces “failed to connect”.
        
          
        
          
        
            
            
        An API that describes itself
        
            
        Bound to 127.0.0.1 only, bearer token required. GET /api/routes lists every route this build serves. A test pairs every Tauri command with either a route or an explicit “GUI-only” reason, so a new capability cannot ship API-invisible without failing the build.
        
          
        
        
        

        
        # two routes answer without a token, because a caller working out why
# nothing else responds should not have to authenticate to find out why
curl http://127.0.0.1:8765/api/health
#   enabled · bound · answering · tokenPresent · tokenAccepted
#   five separate questions, five separate answers

curl http://127.0.0.1:8765/api/routes | jq -r '.routes[] | "\(.method)\t\(.path)"'
        

        
        
          
        
            
        app_read
        
            
        GET any API path. The model starts at /api/routes — that is its catalog of what it can do. “Why can't you see my email?” becomes answerable.
        
          
        
          
        
            
        app_control
        
            
        POST / PUT / PATCH / DELETE. Every call goes through an approval prompt. “Switch to dark mode”, “make me a zone for code review”, “file this chat under the Rewrite project” become things the assistant does rather than describes.
        
          
        
        
        

        
        
          
          
        
            Two routes are refused from inside a turn: sending or regenerating a
            message (a turn calling itself — that is what the subchat tools are for), and answering a
            tool approval (the model granting itself permission). Silently adding a connector that
            launches a process is exactly what an injected instruction would ask for, so installing one
            goes through app_control and therefore through you.
